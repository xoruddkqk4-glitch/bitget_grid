# Implementation Plan: 5일선 추세 전환 기준 개편 (MTF 지지선 이탈 필터)

## 1. 개요 (Overview)
현재 [Grid_Bitget.py](file:///c:/Users/user/Desktop/trading_buddy/06비트겟자동매매-4기/week_01-bitget_grid/Grid_Bitget.py)의 **3-State Switching Engine(추세 라이딩)**에서 추세 종료(꺾임 감지) 기준은 다음과 같습니다:
- **기존 기준**: `[라이딩 진입 후 30분 경과(시간 가드)]` AND `[일봉 5MA 기울기 하향]`
- **문제점**: 라이딩 진입 직후 5~10분 만에 급락 장대음봉이 발생해도 30분 동안 매도(익절/손절)를 전혀 하지 못하고 손실이 확대되는 치명적인 취약점이 존재함. 또한 이평선 자체의 기울기는 후행성이 커서 고점 대비 하락이 크게 진행된 후에야 신호가 발생함.

### 개선 목표:
1. **시간 가드(30분) 완전 삭제**: 시간 기준의 인위적인 락을 제거하여 급락 시 즉각 대응 가능하도록 개편.
2. **다중 타임프레임(MTF) 지지선 이탈 검증 도입**:
   - **1차 검증 (일봉)**: `현재가 < 일봉 5MA * 0.995` (-0.5% 하향 이탈)
   - **2차 검증 (4시간봉 즉시 조회)**: 1차 충족 시에만 4시간봉 캔들을 조회하여 `현재가 < 4시간 5MA * 0.995` (-0.5% 하향 이탈) 크로스체크
   - **종료 판정**: 1차와 2차가 모두 참일 때 비로소 추세 라이딩 종료(`방금_꺾임 = True`) 및 청산 분기 진입.
3. **진입 조건 정합성 보완**: 진입 즉시 튕겨 나가는 현상을 방지하기 위해 라이딩 진입 시 `현재가 >= 일봉 5MA` 조건 확인.
4. **API 호출 최적화 (Lazy Evaluation)**: 평소에는 일봉만 체크하고, 일봉 이탈 시에만 4시간봉을 조회하여 Bitget API Rate Limit 완벽 방어.
