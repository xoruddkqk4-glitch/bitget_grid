## 1. 개요 및 배경

### 🚨 2026-10-15 실제 발생한 치명적 고립(Limbo Lock) 사태 분석
2026-10-15 오전 비상 자가치유 롤다운 발동 후, 시세가 103.88에서 107.70까지 반등하여 차수 48~44가 익절되고 43차가 매수되었습니다. 이후 다음 복원 예약가(42차: 108.4539 USDT)를 걸어둔 상태에서 시세가 107.26에서 98.46까지 -8.2% 완만하게 하락했습니다.
그러나 이 과정에서 **12시간 동안 매수도, 매도도, 더미 매수 기록도 전혀 이루어지지 않는 완전 고립 사태**가 발생했습니다:

1. **상단 공백 보호 락의 과잉 적용 (`차수 <= gap_base_level`)**:
   - `gap_orders.json`에 42차 예약이 대기 중이라는 이유로 `차수 <= 45`인 모든 차수가 스킵되었습니다.
   - 이로 인해 현재 보유 중인 43차(107.70) 아래로 하락하는 **44차, 45차 매수 로직이 코드 첫머리에서 `continue`로 건너뛰어졌습니다**.
2. **더미 매수 기록 기회 상실**:
   - 더미 매수는 `create_market_buy_order` 호출 시 `InsufficientFunds` 예외가 발생해야 기록됩니다.
   - 하지만 44차와 45차가 코드 앞단에서 스킵되어 주문 시도 자체를 하지 못했으므로 더미 기록도 남지 않았습니다.
3. **하위 차수(46차 이후)의 체인 단절**:
   - 46차를 사려면 직전 45차의 체결가 또는 가상 더미 기준가가 있어야 합니다.
   - 45차가 오전에 이미 매도되어 비어있고 가상 더미도 생성되지 못했기 때문에, 46차부터 99차까지 모든 차수가 "직전 차수 미보유"로 연쇄 스킵되었습니다.

## 2. 사용자 피드백 핵심 요구사항

> **"쿨링다운이 나오면 상단을 매수해서 예약 매수로 채우고, 완만하게 하락하면 매수를 진행하면서 보유금이 부족하면 더미 매수를 끊김없이 기록하고 싶어."**

### 🎯 3대 핵심 목표
1. **쿨링다운(급락) 발생 시 ➔ 상단 예약 복원 유지**:
   - 40분 내 5회 급락 시 60분 쿨링다운 발동.
   - 쿨링 종료 후 Rebase 시 증거금 부족 시 상위 선(先)손절 ➔ 증거금 즉시 환급 ➔ 바닥 Rebase 실제 체결.
   - 손절로 발생한 상단 공백 구간에 대해 동적 예약 매수(`gap_orders`)를 배치하여, 시세 반등 시 차례대로 상단을 매수하여 채움.
2. **완만한 하락 시 ➔ 무단절 하향 매수 및 더미 매수 추적**:
   - 40분 내 5회 미만의 완만한 하락 시에는 손절/쿨링 없이 하향 그리드를 정상 진행.
   - 가용 현금이 있으면 **실제 시장가 매수 체결**.
   - 보유금이 부족하면 거래소 에러를 포착하여 **더미 매수 기록 + 텔레그램 1회 알림**.
   - 기록된 더미 매수는 다음 차수의 `v_prev`로 연결되어 **44차 ➔ 45차 ➔ 46차 ➔ ... 차수 체인이 100% 끊김 없이 하향 지속**.
3. **상/하향 분리(Two-Way Decoupling) 락 제거**:
   - 상단 복원 예약이 대기 중이어도, **현재 보유 중인 최하단 차수 아래의 하향 차수(44차~)는 공백 락을 적용하지 않고 자유롭게 하락 매수/더미 매수를 허용**.

## 4. `Grid_Bitget.py` 상세 수정 계획

### 수정 1. 공백 보호 조건 정밀화 (하향 차수 개방)
* **기존 코드의 오류**:
  ```python
  # 기존: gap_base_level(45) 이하의 모든 차수를 막아버림 -> 44, 45차 차단
  if has_pending_gap_orders and gap_base_level > 0 and 차수 <= gap_base_level:
      continue
  ```
* **개선 로직**:
  - 보호해야 하는 공백 구간은 오직 **"쿨링 전 상위 보유 차수(M)와 현재 복원된 바닥 차수(bottom_held_level) 사이의 빈 차수"**뿐임.
  - 현재 보유 중인 최하단 차수를 `bottom_held = int(df[df['매도날짜'].isnull()]['차수'].max())`로 동적 추출.
  - `차수 > bottom_held`인 차수(예: 44, 45, 46...)는 **공백이 아니라 정상적인 하향 매수 구간**이므로 보호 락을 적용하지 않고 통과!
  ```python
  # 개선: 상단 공백 구간(M < 차수 < bottom_held)만 일반 매수를 차단하고,
  # 현재 보유 중인 최하단 차수보다 큰 하향 차수(차수 > bottom_held)는 정상 매수/더미 허용!
  bottom_held = int(df[df["매도날짜"].isnull()]["차수"].max()) if not df[df["매도날짜"].isnull()].empty else 0
  if has_pending_gap_orders and bottom_held > 0:
      top_ceiling = int(gap_state.get("top_ceiling", gap_state.get("prev_level", 0)))
      if top_ceiling > 0 and top_ceiling < 차수 < bottom_held:
          continue
  ```

### 수정 2. 더미 매수의 체인 연속성(v_prev) 완벽 보장
* 매수 실패로 `잔고부족_시도기록(Ticker, 차수, 현재가)`이 호출되면:
  - 해당 차수의 `차수`, `현재가`, `타임스탬프`가 JSON 파일에 저장됨.
  - 다음 차수(`차수 + 1`) 루프가 돌 때 `prev_open`이 비어있더라도 `잔고부족_가상차수_조회(Ticker, 차수)`가 이 더미를 찾아 `기준가 = v_prev["price"]`로 사용.
  - 따라서 43차(실보유) ➔ 44차(더미) ➔ 45차(더미) ➔ 46차(더미) ➔ ... 체인이 끊기지 않고 98.46 USDT까지 자연스럽게 추적됨.

### 수정 3. 40분 5회 급락 판정 및 완만 하락 분기 유지
* `최근_총매수시도_고유차수수(df, Ticker, BUY_COOLDOWN_WINDOW_SEC=2400)`:
  - 40분 내에 5회 이상의 급락이 감지되면 비상 쿨링 발동 ➔ 60분 후 Rebase & 자가치유 롤다운.
  - 40분 내 5회 미만인 완만한 하락이면 비상 쿨링 없이 더미 매수만 1회씩 텔레그램으로 조용히 통보하며 불필요한 선손절을 방지.
