# 📋 [구현 계획서] 쿨링 공백 복원 v2.4 — 비상 증거금 부족 자가 치유(Self-Healing) 롤다운 전략 (급락형 전용)

---

## 1. 개요 및 배경

### 🚨 현재 시스템의 치명적 한계 (자금 고갈로 인한 봇 고립)
현재 비트겟 그리드 자동매매 봇은 급락장에서 고차수까지 모두 소진되어 **증거금/가용 USDT 잔고가 부족(`InsufficientFunds` / `insufficient balance`)**해지면:
1. 매수 주문을 단순히 스킵(`return`)합니다.
2. 엑셀에 체결 기록이 남지 않으므로 `최근매수횟수`가 0으로 유지되어 **급락 연쇄 매수 쿨링다운(`BUY_COOLDOWN_WINDOW_SEC=2400`(40분) 내 `BUY_COOLDOWN_BUY_COUNT=5`(5회))이 발동하지 않습니다**.
3. 쿨링다운이 걸리지 않으므로 **하이브리드 Rebase도, 상위 차수 손절을 통한 공백 복원 롤다운도 작동하지 못합니다**.
4. ➔ **결과**: 시세가 -20% 이상 급락해도 봇은 아무런 대응을 하지 못하고, 계좌는 강제 청산(마진콜) 위험에 고스란히 노출되는 심각한 고립(Stuck) 상태에 빠집니다.

## 2. 사용자 피드백 반영 핵심 설계 원칙 (급락형 한정 리스크 관리) ⭐

사용자의 리스크 관리 피드백을 100% 반영하여, **완만 하락장에서의 불필요한 누적 손실 확정을 원천 차단하고 오직 '급락형 파동'에만 엄격하게 작동**하도록 설계합니다.

### 🎯 5대 핵심 설계 원칙
1. **급락형 파동에만 엄격 한정 (완만 하락형 제외) ⭐**:
   - 완만한 계단식 하락장에서 손절이 반복되면 실현 손실이 커질 수 있으므로, 완만 하락형 발동 조건은 배제합니다.
   - 오직 **최근 40분(`BUY_COOLDOWN_WINDOW_SEC=2400`) 내 잔고 부족 가상 매수 시도 $\ge$ 5회(`BUY_COOLDOWN_BUY_COUNT=5`)**의 극단적 연쇄 폭락 상황에만 비상 쿨링다운(60분)을 발동합니다.
2. **엑셀 원장 무결성 보존 (가짜 데이터 오염 방지)**:
   - 실제 체결되지도 않은 가짜(더미) 매수 행을 엑셀에 기록하지 않고, **독립된 상태 메모리/파일(`insufficient_buy_state`)**에서 잔고 부족 매수 시도를 추적합니다.
3. **사전 가상 기준가($P_{virtual}$) 기반 정밀 공백 계산 (과잉 손절 원천 차단)**:
   - 쿨링 종료(60분) 후 Rebase 반등 시점의 시장가를 '가상 바닥 기준가($P_{virtual}$)'로 설정하여 **실제 돈을 쓰지 않고도 공백 $N$과 필요한 손절 개수 $K$를 사전에 100% 정밀 계산**합니다.
   - **$N < 2$ (단순 하락)**: 손절 개수 $K = 0$개! ➔ **불필요한 과잉 손절 완벽 차단**.
   - **$N \ge 2$ (공백 발생)**: 필요한 $K = \min(N - 1, 10, len(미청산))$개만 선별 손절.
4. **선(先) 손절을 통한 증거금 즉시 환급 & 유동성 부활**:
   - 산출된 $K$개만큼 상위 최고가 물량을 시장가 강제 손절(`reduceOnly=True`)합니다.
   - 포지션이 청산되면서 **유지증거금 부담이 급감(마진콜 해소)하고 지갑으로 가용 USDT가 즉시 환급**됩니다.
5. **실제 시장가 매수 체결 & 실체결가 기준 동적 재조정 (+0.7%)**:
   - 환급된 현금으로 바닥 Rebase를 **실제 시장가 매수**로 체결합니다.
   - 가상 가격과의 미세한 슬리피지/호가 오차는 완전히 버리고, **실제 체결된 가격($P_{real\_fill}$)을 기준으로 정확히 +0.7% 위에 예약 그물망을 배치**합니다.

## 3. 세부 동작 프로세스 및 플로우차트

```mermaid

    B --> C{최근 40분 내 잔고부족 시도 >= 5회?<br/>(급락형 파동에만 한정)}

    C -->|Yes: 40분 내 5회 급락| E[🧊 '비상 가상 쿨링다운' 발동 60분 매수 동결]
    E --> F[60분 경과 후 하이브리드 Rebase 감시: 저점 대비 +0.7% 반등 대기]
    F --> G{Rebase 저점 반등 +0.7% 조건 충족!}
    G --> H[1. 현재가를 '가상 바닥 기준가 P_virtual'로 설정]
    H --> I[2. 직전가 P_prev와 비교하여 공백 N 선(先) 계산]
    I --> J{공백 차수 N >= 2 ?}
    J -->|No: N < 2| K[손절 0개! 무의미한 손절 원천 차단]
    J -->|Yes: N >= 2| L[3. 필요한 K개 = min N-1, 10 만 정확히 시장가 손절]
    L --> M[4. 손절로 환급된 증거금/현금 USDT 즉시 확보!]
    M --> N[5. 확보된 현금으로 바닥 Rebase '실제 시장가 매수' 체결!]
    N --> O[6. 실제 체결가 P_real_fill 기준으로 +0.7% 동적 예약 매수가 배치]
    O --> P[7. 바닥 위 공백 예약 그물망 가동 및 정상 롤다운 복원!]
```

## 4. `Grid_Bitget.py` 상세 구현 계획

### 수정 1. 잔고 부족 매수 시도 트래커 신설 (40분 윈도우)
- `잔고부족_매수시도_기록(Ticker: str, 차수: int, 기준가: float)`:
  - 타임스탬프, 차수 번호, 기준가를 메모리/상태 파일에 누적.
- `잔고부족_최근시도횟수(Ticker: str, window_sec: int = 2400) -> int`:
  - 최근 40분 이내의 고유 차수 시도 횟수만 집계.

### 수정 2. 급락형 비상 쿨링다운 발동 연동 (`매수실행`)
- 잔고 부족 발생 시:
  ```python
  except (ccxt.InsufficientFunds, ccxt.ExchangeError) as e:
      if 잔고부족_관련_에러(e):
          잔고부족_매수시도_기록(Ticker, 차수, 현재가)
          # 오직 40분 내 5회 급락 시에만 발동!
          if 잔고부족_최근시도횟수(Ticker, BUY_COOLDOWN_WINDOW_SEC) >= BUY_COOLDOWN_BUY_COUNT:
              쿨링시작(Ticker, reason=f"증거금 부족 급락 감지 비상 쿨링 (40분 내 5회)")
  ```

### 수정 3. Rebase 진입 시 '사전 가상 계산 ➔ 선 손절 ➔ 후 실체결' 파이프라인 구현
- 쿨링 만료 후 Rebase 트리거 발생 시점:
  - 현재 잔여 가용 USDT 확인 (`거래소_USDT_잔고조회()`).
  - 만약 1회 매수금액 미만으로 잔고가 여전히 부족한 경우:
    1. 현재가를 `P_virtual`로 설정하고 공백 $N$ 및 필요 손절 개수 $K$를 선(先) 계산.
    2. $N \ge 2$ 및 $K \ge 1$인 경우, **상위 $K$개 시장가 손절(`reduceOnly`)을 즉시 먼저 실행**.
    3. 손절 완료 후 가용 잔고가 충전되었는지 확인.
    4. 충전된 자금으로 **바닥 Rebase 시장가 매수 발주**.
    5. 실제 체결된 가격($P_{real\_fill}$)을 엑셀 25차에 확정 기록.
    6. $P_{real\_fill} \times (1 + 0.007)$로 첫 예약 매수가를 동적 산출하여 배치.

## 5. 안전성 및 엣지 케이스 검증 방안

1. **완만 하락장 손절 억제 검증**:
   - 40분 윈도우를 벗어난 완만한 하락 시 비상 쿨링다운이 발동하지 않고, 기존 포지션을 안전하게 보존하는지 검증.
2. **급락형 파동 트리거 정확성 검증**:
   - 40분 내 5회 잔고부족 발생 시에만 정확히 60분 비상 쿨링이 발동하는지 검증.
3. **과잉 손절 방지 검증**:
   - $N < 2$ (단순 1칸 하락)인 경우 손절 개수가 정확히 $0$개로 산출되는지 확인.
4. **정적 구문 컴파일 검증**:
   - `python -m py_compile Grid_Bitget.py`
